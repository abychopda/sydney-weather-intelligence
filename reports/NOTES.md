## Data sourcing

- Source: Open-Meteo Historical Weather API (archive endpoint), Sydney
  (−33.8688, 151.2093), `timezone=Australia/Sydney`.
- **Timezone matters.** Requesting UTC would shift each Sydney day by 10–11
  hours and mix observations from two local days into one daily aggregate.
- Retrieved 2000-01-01 to 2025-12-31: **227,928 hourly observations, zero
  missing values**, no date gaps, no duplicates. Reanalysis output is
  gap-free by construction.
- 2026 onward deliberately untouched — reserved as production data.
- Regenerated by `uv run python -m weather_intelligence.dataset`.

## Target construction

- **Daily aggregation applied before the formulas**, not after. The formulas
  are non-linear (MAX/MIN/ABS) so the order changes the result. The
  constants settle it: `precipitation / 20` and `snowfall / 15` are daily
  totals, not hourly rates. Computing hourly would leave the rain term at
  ~1.0 always, making 15% of the index dead weight.
- **Confirmed by the subject coordinator** on the Canvas discussion board.
- Aggregators: mean for temperature, humidity, wind, cloud; **sum** for
  precipitation and snowfall; **max** for wind gusts. Comfort reflects
  typical conditions; hazard reflects the worst moment of the day.
- ⚠️ **Discrepancy to note in the report:** the coordinator's reply listed
  "minimum visibility" in the WHI slot where the brief's formula specifies
  `CloudHazard = MIN(CloudCover / 100, 1)`. We followed the brief's formula,
  treating the reply as a slip carried over from another variant.

## Modelling windows (different per target — deliberate)

| Target | Window | Reason |
|---|---|---|
| CCI | 2015–2025 | Mean CCI drifted down ~4 points since 2000 (74 → 70). Training on a climate that no longer exists is counterproductive for a model deployed against 2026. |
| WHC | 2000–2025 | Hazard bands are absolute thresholds, so drift matters less, and rare classes need every example. High Risk grows 72 → 274. |

## WHC class imbalance (for the limitations section)

2000–2025, 9,497 days: Low 5,242 · Moderate 3,970 · **High 274** · **Extreme 11**.

- **Extreme Risk is 11 days in 26 years** — roughly one every 2.4 years.
  Extending history barely helps (3 days in 2022–2025 → 11 in 2000–2025).
- All 11 are identifiable storm events (Feb 2020 east coast low: 138 mm rain,
  102 km/h gusts; March 2022 floods).
- `snowfall` is **identically zero** for all 9,497 days, so 10% of the WHI
  weight is a constant and can carry no information.
- Splits at 2018 / 2022 put 4 / 4 / 3 Extreme days in train / val / test —
  barely enough to evaluate, nowhere near enough to learn.
- ⇒ Accuracy is meaningless. Use macro-F1, balanced accuracy, per-class recall.

## Leakage controls

- Feature functions shift **backwards only**; non-positive lags raise.
- `make_supervised_frame` is the single place a forward shift is permitted.
- **Embargo** of `horizon` days at each split boundary, asserted in-notebook.
- Chronological splits, never random — weather autocorrelation would
  otherwise put near-duplicate days either side of the boundary.
- Scaler fitted on **train only**, matching what the deployed API can know.
- Test suite includes a truncation-invariance check that recomputes every
  feature on a shortened series; verified it fails when a leak is injected.

## CCI Experiment 1 — Ridge baseline (results)

Test set = 2024-07-01 → 2025-12-31. 92 features, 2,921 training days.

| Model | MAE h1 / h2 / h3 | R² h1 / h2 / h3 |
|---|---|---|
| **Ridge** | **6.49 / 7.31 / 7.50** | **0.449 / 0.292 / 0.245** |
| Persistence | 7.56 / 9.10 / 9.59 | 0.250 / −0.098 / −0.247 |
| Seasonal mean | 8.71 / 8.71 / 8.69 | 0.049 / 0.039 / 0.042 |

Selected alpha: 100 (h1), 1000 (h2, h3).

**Findings worth reporting:**

1. **Persistence → climatology transition.** Top coefficient shifts from
   today's CCI at h1 (2.99) to the 30-day rolling mean at h3. Calendar
   features climb from ~rank 16 to ~rank 7. Learned, not imposed.
2. **Persistence posts negative R² at h2/h3** — worse than predicting the
   mean. Seasonal baseline R² is only 0.05, so seasonality alone is weak;
   the model's value is in blending the two.
3. **Wet-day failure.** MAE 5.67 (dry) / 5.63 (1–10 mm) / **15.97 (>10 mm)**.
   On wet days the model is optimistic **98% of the time**, mean error −15.8.
   This is the clipped rain component a linear model cannot represent.
4. **Overall bias is ~zero (−0.14) and this is misleading** — a small
   optimism on 504 dry days cancels a large one on 44 wet days.
5. **Hot days were expected to fail and did not** (MAE 4.58, better than
   average). The temperature non-linearity is mild across Sydney's range.
   ⇒ Expect gains from non-linear models to come from rain, not temperature.
6. Band agreement: 63.3% / 61.8% / 61.9%. Barely degrades with horizon
   because added error stays inside a 20-point band.

## Serving design (why the API must fetch live data)

- The model is a formula, not a stored forecast. Its strongest input is
  **today's CCI**, which needs the weather on the requested date itself;
  rolling means need up to **30 days** of preceding history.
- Calendar features alone = the seasonal baseline = R² 0.05. Recent weather
  is what takes it to 0.45.
- ⇒ For a 2026 date the API fetches ~30 days of hourly data ending **on**
  that date. `required_history_days(recipe)` derives the number from the
  recipe, so changing the recipe changes the fetch automatically.
- **Must never fetch past D.** For a past 2026 date the archive already
  holds D+1…D+7; using them would be production leakage.
- Brief's "data up to 2025" governs train/val/test. 2026+ is explicitly
  "data in production" — exactly what the API consumes live. No conflict.

### Refactor: single feature pipeline (done)

The recipe previously lived as notebook cells F.1–F.4, which the API would
have had to reproduce by hand — classic **training/serving skew**. Now
`features.build_daily_features(hourly, recipe)` is the single source, and the
recipe is saved **inside each artefact**. Scaler + model are bundled with
`make_scaled_pipeline`, removing the other skew risk.

Verified behaviour-preserving: feature frame byte-identical (9497 × 93),
test metrics unchanged (MAE 6.489 / 7.310 / 7.498).

**End-to-end serving test on an unseen date (2026-08-15):** fetched 720
hourly rows, built all 92 features complete, predicted 67.9 / 69.4 / 69.7
against actuals 62.8 / 51.9 / 58.1. Errors 5.1 / 17.5 / 11.6 — the middle
day was a deteriorating wet period, consistent with the known wet-day
weakness. One sample, not a benchmark, but the full path works.

## WHC Experiment 1 — Logistic baseline: **HYPOTHESIS REJECTED**

Window 2000–2025, horizon 7 days, 116 features. Split 2018 / 2022.
Train 6,509 · Val 1,454 · Test 1,454 (2022-01-01 → 2025-12-24).

| Model | macro F1 | bal. acc | High recall | Extreme recall | days flagged |
|---|---|---|---|---|---|
| Logistic, unweighted (selected) | 0.241 | 0.262 | **0.000** | 0.000 | **0 / 1454** |
| Logistic, balanced C=0.001 | 0.198 | 0.236 | 0.343 | 0.000 | 659 / 1454 |
| Majority / persistence / seasonal | — | — | — | — | — |

**The decisive numbers: ROC AUC 0.378, average precision 0.039 (base rate
0.050).** Both *below random*. The model's ranking of hazardous days is
anti-correlated with reality, so no threshold, reweighting or recalibration
can rescue it. Max hazard probability assigned to any day: 0.263.

### Four findings worth reporting

1. **Horizon is the binding constraint.** Same-day correlations with WHI are
   strong; at +7 days they collapse to near zero (section D.1). Predicted in
   advance, confirmed by the persistence baseline.
2. **Drift made it actively worse — and this was NOT anticipated.** Class
   balance shifted train → test: Low 60% → 48%, Moderate 39% → 52%. Choosing
   the 26-year window to harvest rare examples traded relevance for volume,
   and traded badly. Sub-random AUC is the signature of applying an outdated
   relationship. ⇒ **Revisit the Option 1 window decision for WHC.**
3. **Macro F1 and balanced accuracy both failed as selection criteria.** Both
   were chosen specifically to resist imbalance, and both preferred the
   never-warns model over one catching 34% of hazards, because class
   weighting loses ground on common classes faster than it gains on rare
   ones. No single aggregate encoded the business objective; the per-class
   recall table did.
4. **Extreme Risk is not learnable.** 4 training examples, 0% recall in every
   configuration. Document as a service limitation, not a modelling target.

### Consequences for the API

- `/model-metadata` **must** expose per-class recall — an aggregate figure
  would hide that hazardous classes are undetected.
- Endpoint docs must state the hazard model is experimental and **not a
  safety input**. A service that silently never warns is the most dangerous
  failure mode available.
- Artefact still saved so the deployment can be validated end to end; the
  API contract does not depend on model quality.

### WHC experiment 2 — ranked

1. **Recent-only window (2015+)** — cheapest and most informative, given
   AUC < 0.5. Costs: High 274 → ~158, Extreme 11 → 9.
2. **Gradient boosted trees** — hazardous days are a *conjunction* (heavy
   rain AND severe gusts AND total cloud); linear models can't express it.
3. **Binary reframing** — hazardous vs not, still reporting 4 classes as
   specified. Raises the positive class from 0.12% to ~3%.
4. **External predictors** — synoptic/oceanic indices. Local surface
   observations may simply not contain 7-day information.

## Next experiments (ranked by expected uplift)

1. Gradient boosted trees — can represent the clipped rain component.
2. Rainfall-specific features — binary wet-day flag, rolling rain-day counts,
   antecedent rainfall. Millimetre totals that are >50% zeros are a poor input.
3. Asymmetric / quantile loss — aligns the objective with the business cost
   of over-predicting comfort.

## CCI Experiment 2 — Random Forest: **HYPOTHESIS REJECTED**

Window 2015–2025, 96 features, split 2023-01-01 / 2024-07-01, 2,919 train rows.

| Model | test h1 | h2 | h3 | val h1 | CV h1 |
|---|---|---|---|---|---|
| **Ridge (alpha=1000)** | **6.489** | **7.350** | **7.527** | 6.231 | 6.234 |
| Random Forest (tuned, change target + recency weights) | 6.570 | 7.630 | 7.694 | **6.070** | **6.093** |
| Gradient boosting | 6.727 | 7.829 | 7.966 | 6.149 | 6.417 |
| Ridge + Forest average | 6.437 | 7.430 | 7.559 | 6.094 | — |
| Persistence | 7.560 | 9.093 | 9.589 | — | — |
| Seasonal average | 8.721 | 8.716 | 8.691 | — | — |

Ridge test metrics: RMSE 8.561 / 9.710 / 9.995 · R² 0.447 / 0.288 / 0.241
Band agreement 65.2% / 61.9% / 62.1% · within 5 points 49.3% / 45.4% / 42.9%
Too optimistic on 46.2% of days; mean overshoot when optimistic 7.33 points.
RF best params: max_depth 15, min_samples_leaf 5, max_features 0.3 (h1, h3) / 1.0 (h2).

**Findings:**
1. **Validation and test disagreed.** RF won on CV (6.093 vs 6.234) and on
   validation (6.070 vs 6.231), lost on test. Selecting on tuning scores would
   have shipped the worse model. 544 validation days → 0.15 MAE is noise.
2. **Wet days:** Ridge 5.61 (dry) / 5.61 (light) / **16.56** (>10 mm).
   Forest 5.78 / 5.69 / **15.91**. The tree fixed a little of the rain problem
   and lost more on the 92% of days that are dry or light.
3. **Rain features are used only with the change target.** Predicting the level
   (G.2): precipitation rank 55, `is_wet_day` rank 90 of 90. Predicting the
   change (J.4): precipitation rank 2, `precipitation_max` 4, `precipitation_hours` 7.
4. **Feature reduction never helped.** All 96 = 6.198 val MAE; 6 near-duplicates
   removed (0.95 threshold) = 6.235; top 40/30/20 = 6.290 / 6.339 / 6.402.
5. **Ceiling ~6.4–6.7 MAE** across linear, bagged trees, boosted trees,
   differenced target, recency weights, feature selection and a blend.

**No model saved.** Exp 1 Ridge stays the final, deployed model. A Ridge fitted
on the 96-feature set matched it at h1 (6.489) and was slightly worse at h2/h3,
confirming the six rain features are not worth redeploying for.

## WHC Experiment 2 — in progress

Window 2000–2025 (primary), 125 columns → **91 selected**, split 2018 / 2022,
6,509 train rows. Horizon 7 days.

**Class counts and shares per split:**

| | train | val | test | train % | val % | test % |
|---|---|---|---|---|---|---|
| Low | 3830 | 706 | 665 | 58.8 | 48.6 | 45.7 |
| Moderate | 2532 | 686 | 716 | 38.9 | 47.2 | 49.2 |
| High | 143 | 58 | 70 | 2.2 | 4.0 | 4.8 |
| Extreme | 4 | 4 | 3 | 0.1 | 0.3 | 0.2 |

**Drift is confirmed and substantial:** Low 58.8% → 45.7%, Moderate 38.9% →
49.2%, and High Risk **more than doubles** (2.2% → 4.8%). Recent Sydney years
are genuinely more hazardous.

**The horizon is the binding constraint.** Same-day vs +7-day correlation:

| Variable | same day | +7 days | variance explained at +7 |
|---|---|---|---|
| cloud_cover | 0.799 | 0.063 | 0.004 |
| precipitation | 0.746 | 0.021 | **0.000** |
| whi | 1.000 | 0.063 | 0.004 |
| temperature_2m | 0.103 | **0.136** | **0.019** ← best |

Fade by horizon (whi): 1d 0.487 · 2d 0.211 · 3d 0.118 · 5d 0.073 · 7d 0.063 · 10d 0.065.
Flat by 5 days — 7 days is no different from 10.

**Window length test (F.2)** — correlation of the rolling WHI mean with the
target 7 days out:

```
7d 0.105 · 14d 0.129 · 30d 0.141 · 60d 0.158 ← peak · 90d 0.157 · 120d 0.145 · 180d 0.103
```

Inverted U. 60 days kept. Longer windows blur the seasonal pattern that gives
these features their value. **My prediction that longer would keep improving
was wrong** — tested and documented in F.2.

**Rain features beat raw rainfall here** (unlike CCI): `rain_days_roll30` 0.064
vs `precipitation` 0.021. "Has it been a wet month" survives 7 days; "did it
rain today" does not.

**Feature selection (G.2, 0.85 threshold):** 123 → 91 (32 near-duplicates
removed). Validation macro F1: all 123 = 0.2746 · **no duplicates (91) = 0.2752**
(chosen) · top 20 = 0.2742 · top 30 = 0.2659 · top 40 = 0.2674.

**Importance is flat** — top feature 0.034 (vs 0.37 for `cci` in the comfort
model). Key ranks: `whi_roll60_mean` #3 · `temperature_2m` #20 · **`whi` #42**
· `rain_days_roll30` #75 · **`snowfall` #91 with importance exactly 0.00000**.
Today's hazard ranks 42nd while its 60-day average ranks 3rd — the reverse of
the comfort model, exactly as D.1 predicted.

**Metric finding (recorded in section I).** No aggregate metric encodes the
business objective. Demonstrated on the real test distribution with three
imaginary models:

| Model | accuracy | balanced_acc | macro_F1 | recall_High | caught | false alarms |
|---|---|---|---|---|---|---|
| Always Moderate | 0.492 | 0.250 | 0.165 | 0.000 | 0 | 0 |
| **Never warns** | **0.673** | **0.354** | **0.345** | 0.000 | **0** | 0 |
| Over-warns | 0.479 | 0.322 | 0.302 | 0.314 | 24 | 400 |

**Balanced accuracy prefers the silent model too** (0.354 vs 0.322), so
switching to it would not have fixed experiment 1. Only per-class recall and
the caught/false-alarm counts reveal the difference. ⇒ Tune on macro F1, report
`hazard_summary` alongside, decide with the threshold sweep.
